| D-05 | LLM: OpenRouter, a **chain of 7 free models** tried in order by measured accuracy (`OPENROUTER_MODELS`, defaults to `DEFAULT_OPENROUTER_MODELS` in `src/config.ts`): `dots-studio/dots-3-note-preview:free`, `liquid/lfm-2.5-2.6b:free`, `nvidia/nemotron-3-super-120b-a12b:free`, `google/gemma-4-31b-it:free`, `qwen/qwen3.8-27b:free`, `google/gemma-4-26b-a4b-it:free`, `openrouter/free` (OpenRouter's own auto-router across whatever free model is available, as the final catch-all) | Accepted (changed on 2026-09-28) | Supersedes the earlier proposal `gemini-3.8-flash` (PR #1) and the single-model Gemini decision below. Eligible: none of the 7 models is from Anthropic or OpenAI (Beyond the Big Two track); `gemma-4` and `qwen3.8` are explicitly listed as eligible families in the official rules. Reason for the switch: Gemini's free daily quota (20 req/day per model) was exhausted on both configured models (`gemini-2.5-flash-lite` and the `gemini-3.5-flash` fallback) with billing still unconfirmed on the Google account, which blocked testing the bot with real usage (see `palavra-notes/conclusao-desenvolvimento.md`, section 5). Verified live on 2026-09-28 against `GET https://openrouter.ai/api/v1/models` (460 models total, 20 with zero pricing); excluded from the chain: audio-output models (`google/lyria-3-*`), the `nvidia/nemotron-3.5-content-safety` moderation classifier, and the unlabelled `stealth/space-bunny-alpha` preview (uncertain provenance, not reliably free long-term). The chain is ordered by native `response_format`/`structured_outputs` support first; models without it still work because the JSON schema is also spelled out in the prompt text (see `src/llm/openrouter.ts`), and an invalid answer already falls through to the next model via the pre-existing `callWithFallback` retry/fallback logic in `src/llm/extraction.ts` — no change needed there. **Measured on 2026-09-28** with `eval/openrouter-extraction.ts --all` against the 20-case fixture set (valid JSON / type / due / owner): `dots-studio/dots-3-note-preview:free` 100%/90%/100%/92% (338 s, no failures); `liquid/lfm-2.5-2.6b:free` 75%/60%/70%/91% (472 s, degraded near the end by the account quota below, not the model); `nvidia/nemotron-3-super-120b-a12b:free` 25%/20%/50%/80% before giving up early — root cause found and fixed: the request had no `max_tokens`, so this model's reasoning output truncated the JSON answer (`Unexpected end of JSON input`); now sends `max_tokens: 2048` (see `src/llm/openrouter.ts`), not yet re-measured. `google/gemma-4-31b-it:free`, `qwen/qwen3.8-27b:free` and `google/gemma-4-26b-a4b-it:free` returned 0% — not an accuracy problem, the *upstream* provider was rate-limited for all OpenRouter users at test time ("temporarily rate-limited upstream"), independent of our account; retry another day for real signal. **Separately discovered:** OpenRouter's free tier is capped **per account**, not per model — 50 free-model requests/day, or 1000/day after adding $10 in credits (`"Rate limit exceeded: free-models-per-day. Add 10 credits to unlock 1000 free model requests per day"`); this run's own retries used up the day's 50 before finishing, which is why `openrouter/free` also came back 0%. 50/day is too low for real multi-day group usage (judging criterion 2) — **adding $10 in credits to the OpenRouter account is recommended** before the real-usage phase (F4). Chain reordered above by these measured numbers, not just declared schema support. Re-run `eval/openrouter-extraction.ts --all` (replaces `eval/gemini-extraction.ts`) to re-measure each model's accuracy against the same fixtures used for the original Gemini check (see `docs/evidence/gemini-model-check.md` for that earlier evidence, kept as historical record). — **Earlier decision (2026-09-24, superseded):** single LLM Gemini, model `gemini-2.5-flash-lite`, via the `@google/genai` SDK. `gemini-2.5-flash-lite` was the only model that completed the extraction check: 100% valid JSON, 100% type accuracy and 100% owner accuracy on the first 16 cases; `gemini-3.8-flash` returned 403 and then 503 in every attempt. Only 2 of 9 due dates were wrong, which the prompt refinement fixed. The Google account was the one that owned the API key, created by Maria (Mari); billing was never confirmed enabled, and the free tier hit its quota (429). Fallback rule added 2026-09-25: `GEMINI_FALLBACK_MODEL` (`gemini-3.5-flash`) took over when the primary kept failing (503/429) or returned invalid output. |
