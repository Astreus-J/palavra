# Fact model v1

A **fact** is the unit of memory Palavra writes to Walrus (one `remember` call per fact).
Implementation: [`src/core/fact.ts`](../src/core/fact.ts). Tests: `src/core/fact.test.ts`.

## Format

```
[COMMITMENT v1] id=c_7f3a9b21 supersedes=- author=tg%3A123456 owner=Maria due=2026-09-26 topic=- at=2026-09-25T10%3A00%3A00.000Z task=send%20the%20budget
Maria committed to sending the budget by Friday, 2026-09-26.
```

- **Line 1 is the header**: `[TYPE vN]` followed by `key=value` pairs separated by single spaces.
- **The rest is the text**: a human-readable sentence. It is what the embedding search sees
  and what the bot shows to users. It may span several lines and is trimmed.
- Values are percent-encoded (`encodeURIComponent`), so spaces, `=` and accents are safe.
  A missing value is written as `-`; a literal `-` is written as `%2D`.
- Key order is fixed on write (`id supersedes author owner due topic at task`); the parser accepts any
  order, rejects unknown or duplicate keys, and only requires `id`, `supersedes` and `author`.

## Types

| Type | Meaning | `supersedes` | `owner` |
|---|---|---|---|
| `DECISION` | the group decided something | must be empty | optional |
| `COMMITMENT` | someone takes a task | must be empty | **required** |
| `AMENDMENT` | changes a deadline or task already agreed | **required** | optional |
| `COMPLETION` | someone finished something | **required** | optional |

Facts are never edited or deleted (Walrus is append-only). A change is a new
`AMENDMENT` that points at the previous fact; the State Resolver follows the chain to the last link.

## Fields

| Field | Format | Notes |
|---|---|---|
| `id` | `<t>_<8 hex>` where `t` is `d`, `c`, `a` or `k` | generated by `newFactId(type)` |
| `supersedes` | an `id`, or `-` | the fact this one changes or closes |
| `author` | channel-scoped id, e.g. `tg:123456` | who wrote the message |
| `owner` | free text (a person's name) | who is responsible; may differ from `author` |
| `due` | ISO date `YYYY-MM-DD` | in the group's timezone; real calendar dates only |
| `topic` | short key, e.g. `delivery` | optional, used by `/decisions` (P1) |
| `task` | short title, 1-120 characters | optional; set on the fact that opens an item (`DECISION` / `COMMITMENT`) and shown by `/pending` and `/history`. Facts written before it existed simply have none |
| `at` | ISO instant with milliseconds, e.g. `2026-09-25T10:00:00.123Z` | when the message happened; stamped by the ledger. Orders facts independently of Walrus write time, so a ledger rebuilt from Walrus resolves to the same state |

## API

- `serializeFact(fact)` / `parseFact(text)`: round-trip is lossless (covered by tests).
- `validateFact(fact)`: throws `FactError` when a v1 rule is broken.
- `looksLikeFact(text)`: cheap filter for recalled memories that are not facts.
- `newFactId(type)`, `isValidIsoDate(value)`.

Both `serializeFact` and `parseFact` validate, so an invalid fact can neither be written nor read back.
An unsupported version (`v2`) is rejected explicitly, which leaves room for a future migration.
